# ТЗ для Claude Code: сохранить адаптацию телефона и реализовать офлайн-просмотр

Актуализировано 29 сентября 2026 года. Эта редакция заменяет прежнее ТЗ «сначала ПК, затем Android». Сейчас приоритет — существующий AnixApp для Android-телефона. Не начинай заново ПК-этап и не создавай новый проект.

## 1. Цель и исходное состояние

Нужен APK, в котором можно выбрать озвучку, скачать серии или сезон, затем без интернета открыть приложение и смотреть скачанное с сохранением позиции. Видео должны быть организованы внутри приложения, без поиска по папкам.

Рабочий репозиторий пользователя: https://github.com/glory7sa/anixapp-test
Исходная ветка с адаптацией: `origin/android-phone-offline`.
По присланному логу пользователя коммит `a323690` («phone adaptation») содержит 18 изменённых файлов и успешно отправлен в эту ветку. Это подтверждение на момент лога, а не проверка текущего состояния GitHub. Проверь актуальный remote, ветки и коммиты самостоятельно. Предыдущая сессия Claude Code находилась в `claude/android-phone-offline-…` на коммите `3a145fd`, совпадавшем с main, и поэтому не видела адаптацию.

У пользователя Windows, локальная папка: `C:\Users\Kenny\Desktop\anixapp-test-main`. Веб-сессия Claude Code не доказывает состояние этой папки. Не утверждай, что локальные файлы пользователя обновлены или перезаписаны, если ты работаешь только с облачной копией.

По словам пользователя API сейчас работает; при прежней правке исчез сервер/пункт «Германия», затем это исправлялось. Наличие последнего исправления в GitHub и приложенных архивах пока не подтверждено. Нужно сохранить рабочее подключение, Германию и остальные серверы, настройки и выбор пользователя.

## 2. Наработки и степень доверия

В пакете `AnixApp_Android_Offline_Handoff.zip` находятся это ТЗ, оригинальные архивы №2–5, распакованная копия файлов №5 в `reference-files-v5/`, SHA-256-манифест и команды проверки локальной папки. Это справочные материалы для сравнения, не полный репозиторий, не готовый APK и не инструкция перезаписать проект.

| Архив | Состав и назначение |
|---|---|
| №2 | 10 файлов: телефонная навигация, вкладки, стили, настройка вида, определение телефонного режима, сборочный скрипт |
| №3 | 13 файлов: дополнительно мост ориентации, MainActivity и интеграция плеера |
| №4 | 15 файлов: дополнительно настройки API, браузерный мост и правки сборки |
| №5 | 16 файлов: дополнительно CdnBridgeWebViewClient для обработки CDN |

Состав сравнен: №5 включает все пути из №2–4. Но он не обязательно новее текущего GitHub или последнего исправления Германии. В №5 нет `package.json` и `yarn.lock`, которые присутствуют в списке 18 файлов коммита. Полную сборку из одних архивов получить нельзя.

В `src/constants/apiEndpoints.ts` архива №5 перечислены прямые хосты и резервный прокси с названием `AnixApp proxy`; явного названия «Германия» в этом файле нет. Это НЕ доказывает отсутствие сервера во всём проекте и НЕ позволяет приравнять прокси к Германии. Без ключа резервный прокси в телефонном режиме скрывается функцией `isBackupProxyAvailable()` — проверь, связано ли это с жалобой пользователя, не делай вывод заранее.

Предыдущий файл `anixart.apk`, если доступен, — лишь ориентир поведения. Не переходи к его модификации или декомпиляции вместо продолжения существующего проекта. Архивы и ТЗ не подтверждают успешный запуск на устройстве.

## 3. Обязательный этап 0: установить, что реально есть

Сначала прочитай инструкции репозитория. До изменения кода проверь состояние рабочего дерева, origin и текущую ветку. Не выводи секреты из URL, конфигурации и .env.

Выполни доступные проверки:

```sh
git status --short --branch
git branch --show-current
git log -5 --oneline
git fetch origin
git branch -a
git log -5 --oneline origin/android-phone-offline
git diff --stat origin/main...origin/android-phone-offline
git merge-base --is-ancestor a323690 origin/android-phone-offline
```

Последняя команда проверяет предка, но сама по себе не доказывает, что изменения позднее не отменены. Если хеш неизвестен или история переписана, сравни содержимое и историю файлов, а не объявляй правки потерянными.

Сделай краткую таблицу: функция → файл/символ → состояние в актуальной ветке → отличие от №5 → действие. Статусы: «есть и сохранено», «есть более новая реализация», «отсутствует», «требует проверки». Для совпадения байтов можно использовать манифест; различие хеша не означает ошибку или потерю функции.

Проверь как минимум:
- PhoneBottomNav, телефонные стили и компактные вкладки;
- определение телефонного режима без изменения ПК/TV;
- портретную ориентацию интерфейса и горизонтальную ориентацию полноэкранного плеера;
- скрипт сборки и соответствующую команду package.json;
- обработку API, выбор серверов и сохранение настроенного сервера;
- обработку обложек/CDN;
- наличие и актуальность ТЗ.

Пользователь не знает, были ли файлы перезаписаны. Отвечай только по данным: текущий код, diff, коммиты и доступный reflog. Если нельзя установить прошлое действие, скажи это и опиши нынешнее состояние. Один `git fetch` не обновляет файлы рабочего дерева.

## 4. Сохранение и восстановление правок

Продолжай в отдельной разрешённой сессией ветке `claude/…` от актуальной `origin/android-phone-offline`. Не вноси изменения напрямую в `main` или `android-phone-offline`. Если в текущей ветке уже есть работа, сначала сохрани её и сравни истории; не теряй её при смене основы. Не используй `reset --hard`, `clean -fd`, force push или слепое копирование архива поверх проекта.

Если часть адаптации отсутствует, восстанови её минимальными изменениями, используя №5 как образец, и согласуй с текущими интерфейсами проекта. Более новые исправления сохраняй. Не распаковывай архивы последовательно поверх рабочего дерева. Не копируй целиком большой файл плеера ради небольшого изменения ориентации.

Германия: найди реальное имя, адрес и реализацию в актуальном коде/истории/настройках. Не придумывай URL и не переименовывай другой сервер в Германию. Если данных для восстановления нет, запроси только недостающий адрес, скриншот или файл. Другую независимую работу можно продолжать. Не считай сетевую ошибку из облачной среды доказательством неработоспособности сервера на телефоне.

Не удаляй варианты серверов ради устранения ошибки подключения. Нужны корректная обработка ошибок и сохранение пользовательского выбора. Не встраивай реальные приватные ключи в коммит или APK. Учти, что переменные VITE_* оказываются в клиентском бандле; наличие ключа проверяй без вывода значения. Не ослабляй TLS-проверку как способ починить CDN.

## 5. Дизайн, данные и границы задачи

Сохрани текущие светлую и тёмную темы, рабочую телефонную адаптацию, настройки вида и навигацию. Разрешены необходимые кнопки, значки и индикаторы в существующем стиле. Предпочтительные пункты:
- «Загрузки»: тайтлы, серии, озвучки, запуск, продолжение, удаление;
- «Информация о загрузках»: очередь, прогресс, объём, ошибки и повтор.

Переиспользуй существующие подходящие экраны. Не делай редизайн, несвязанный рефакторинг или массовое обновление зависимостей.

Сохраняй аккаунт, закладки, историю, настройки, скачанные файлы и прогресс. Изменения схемы данных — только с совместимым чтением/недеструктивной миграцией и проверкой на копии. Очистка веб-кэша не должна удалять загрузки или позицию. Не требуй очистить данные/удалить приложение как штатный способ обновления. Перед установкой обновления проверь applicationId, versionCode и совместимость подписи; не обещай установку поверх при отсутствии проверки.

## 6. Функциональные требования

### Загрузки
1. Выбор озвучки до скачивания, одна серия или все доступные серии сезона/тайтла. Дополнительно — диапазон и только непросмотренные, после основного сценария.
2. Устойчивая идентификация тайтла, серии и озвучки; источник и качество учитывай согласно реальной модели. Не вводи новую схему ключей без проверки существующей и миграции. Не заменяй озвучку автоматически и не создавай дубликаты.
3. Состояния очереди: ожидание, загрузка, пауза, завершено, ошибка, отмена. Зелёный прогресс и процент при известном объёме; честный неопределённый индикатор при неизвестном. Счётчик пакета «Готово Н из М».
4. Пауза, продолжение, отмена и повтор только неудачных. Ошибка одной серии не останавливает пакет. Не обещай докачку с места, если сервер её не поддерживает.
5. Предварительно показывай количество серий и объём, если известен. Обрабатывай потерю сети, истёкшую ссылку, нехватку места и прерывание без ложного статуса завершения.
6. Устойчивая очередь после закрытия/перезапуска; корректная работа в фоне и при выключенном экране средствами Android. Выбор механизма обоснуй текущей архитектурой и ограничениями целевой версии Android.
7. «Скачано» — только после завершения и проверки результата. Ненулевой размер сам по себе не доказывает полноту видео. Для HLS должны локально присутствовать необходимые сегменты, плейлисты и другие разрешённые для сохранения зависимости, либо проверенный автономный контейнер. Один сетевой m3u8 не является скачанной серией. DRM не обходить; неподдерживаемый источник обозначать явно.

### Автономная библиотека и плеер
8. Названия, обложки, серии, озвучки и статусы доступны локально. Холодный запуск без сети не блокируется входом или бесконечной проверкой соединения; не обходи серверную авторизацию для онлайн-функций.
9. Индикатор «Офлайн». Скачанные серии доступны, известные нескачанные — серые с понятной подписью. Не показывай неизвестный полный список как достоверный: сохраняй метаданные заранее.
10. Запуск скачанного прямо из приложения, перемотка, продолжение с сохранённой серии и секунды. Офлайн-воспроизведение не должно требовать обновить сетевую ссылку.
11. Прогресс хранить локально периодически, на паузе и при уходе с экрана, с учётом аварийного завершения. Раздельно хранить «просмотрено», наличие файла и позицию; не переносить позицию между разными озвучками без учёта таймингов.
12. Если вариант не скачан, объяснять причину. Не переключаться незаметно на другую серию/озвучку. При восстановлении сети не перезаписывать локальный прогресс устаревшей историей.

### Удаление
13. Удалять одну серию, выбранные просмотренные серии или загруженный тайтл. История и позиция сохраняются. Автоматическое удаление не требуется.
14. Если файл удалён вне приложения, корректировать доступность без потери истории. Отсутствие разрешения/временно недоступное хранилище отличать от подтверждённого удаления.

## 7. Реализация по этапам

A. Аудит веток и файлов, сохранение основы, восстановление только недостающей телефонной адаптации, проверка серверов и базовой сборки.
B. Минимальный сквозной сценарий: скачать одну серию выбранной озвучки → увидеть в библиотеке → запустить в авиарежиме → закрыть и продолжить с сохранённой позиции. Сразу заложить корректное хранение и совместимость данных.
C. Очередь/пакеты, фон, восстановление после прерываний, ошибки, пауза и повторы.
D. Групповое удаление, дополнительные варианты выбора серий и итоговая проверка регрессий.

Не откладывай проверку каждого этапа до конца. Если часть уже реализована и проверена, переиспользуй её. Изучай существующие Downloads.svelte, stores/downloads.ts, download-queue-client.ts, платформенные мосты и плеер по фактическому дереву репозитория. Не предполагай, что Electron IPC, Node fs или десктопный FFmpeg доступны в Android. Имена из старого ТЗ — подсказки для поиска, а не доказательства текущей структуры.

## 8. Проверки и критерии приёмки

До правок зафиксируй исходный результат сборки и существующие ошибки. Выбери менеджер пакетов и команды по package.json, lock-файлу и инструкциям репозитория. Не меняй lock-файл без обоснованной необходимости. Собери Android APK, если среда позволяет; иначе сообщи точный блокер и проверенную по проекту команду для Windows.

Проверки на устройстве (если устройства нет — явно оставь непроверенными):
- вход, каталог, поиск, карточка, выбор серии и озвучки, закладки, история;
- API работает; Германия и остальные реальные варианты сохранены; выбранный сервер переживает перезапуск;
- обложки загружаются, обе темы и нижняя навигация сохранены;
- плеер переходит в горизонталь и возвращает портрет после выхода;
- скачать несколько серий; повтор не создаёт дубль, другая озвучка — отдельный вариант;
- авиарежим → полностью закрыть приложение → открыть → запустить локальную серию;
- остановить на 08:37 → закрыть → открыть → продолжить примерно с этой позиции;
- недоступная серия имеет объяснение; онлайн-плеер продолжает работать;
- ошибка одной загрузки не мешает другим; повтор не перекачивает успешные;
- сворачивание, выключение экрана, потеря сети, перезапуск и нехватка места не портят очередь;
- HLS действительно воспроизводится без сети, включая перемотку;
- удаление освобождает место, история остаётся; очистка веб-кэша не удаляет видео;
- установка совместимого обновления сохраняет данные.

Проверка сборки не равна проверке на телефоне. Не утверждай, что всё работает, по одному статическому просмотру. Для первого этапа достаточно релевантных проверок, остальное отметь как будущие критерии.

## 9. Что вернуть пользователю

Краткий отчёт, без огромного пересказа ТЗ:
1. Реальный репозиторий, исходная ветка/коммит и рабочая ветка.
2. Какие прежние правки найдены, какие восстановлены, какие более новые сохранены. Отдельно результат проверки Германии.
3. Что реализовано сейчас и перечень изменённых файлов.
4. Что прошло: анализ кода, автоматические проверки, сборка, устройство; что не проверено и почему.
5. Коммит и факт успешной отправки в свою ветку, если выполнена. Не сливай её автоматически в main или android-phone-offline.
6. APK, если действительно собран, и его исходный коммит; иначе конкретный блокер.
7. Простой следующий шаг для пользователя и короткий сценарий проверки телефона. Команды обновления локальной папки давай только с проверкой незакоммиченных изменений, без принудительного сброса.

Не останавливайся на общем плане, когда код доступен: выполни ближайший законченный этап. Но при отсутствии исходной ветки или противоречии версий сначала установи факты, а не создавай очередную адаптацию вслепую.
